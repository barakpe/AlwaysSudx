A pure timing milestone: the board-wide contradiction reduction was taken out of
the cell write enables, raising standalone Fmax **24.4%** with **no change of any
kind** to cycles or results. No bitstream is published for v6; it is superseded
by v7, which keeps this change and removes a cycle from every guess.

| Result | v5 | v6 |
|---|---:|---:|
| Standalone Fmax used for scoring | 58.10 MHz | **72.30 MHz** |
| Accelerator mapped / fitted LEs | 17,389 / 17,219 | 17,372 / **17,142** |
| Accelerator registers | 2,999 | 2,999 |
| hard1 application cycles | 483 | 483 |
| hard1 assignment score | 8.31 us | **6.68 us** |
| Cycles and grids, 3,739 RTL runs | reference | **byte-identical** |

### What changed

Every one of the twenty worst paths in the v5 standalone report ran from a
candidate register, through the hidden-single union tree and the per-cell forced
terms, into an 81-input OR of `dead_cell` and a 27-input OR of `no_home`, and
from there into the write enable of every cell register. Of that 16.85 ns data
path, 5.77 ns was the reduction itself and a further 4.17 ns was the resulting
roughly 1300-bit enable fanout — about 59% of the path spent on detecting
contradictions rather than on solving.

That reduction only has to choose the next state. Applying forced digits during
a contradicted round cannot corrupt anything: `forced[c]` is nonzero only for
empty cells, so no given or parent assignment is overwritten; every such write
carries the current decision depth; and a contradiction always routes to
`BACK_APPLY`, which clears exactly that depth before the board is read again.
So `propagate` becomes `state == APPLY` and the reduction feeds only the
four-bit state register.

Because nothing about the search changes, the regression is an equality check
rather than a comparison: identical cycles and identical solved grids on the
513-board `standard` set, the 3,191 published holdouts, and the 35 rejection
tests.
