Two changes taken from v5's own timing report: the board-wide contradiction
reduction no longer gates the cell write enables, and the MRV row tournament no
longer has a clock cycle to itself. The hard1 assignment score improves
**8.31 us → 6.70 us** and the mean core-time advantage over opus rises from
3.20x to **4.18x**. Full `.sof` and `.svf` are built and pass 50 MHz timing.
Physical FPGA testing remains to be done.

### What changed

**v6 — the contradiction reduction does not need to gate the writes.** All twenty
of v5's worst paths ended at a cell register's enable input, and roughly 60% of
that 16.85 ns path was an 81-input OR of `dead_cell`, a 27-input OR of
`no_home`, and the ~1300-bit fanout broadcasting the result. But applying forced
digits during a contradicted round cannot corrupt anything: `forced[c]` is
nonzero only for empty cells, every such write carries the current decision
depth, and a contradiction always routes to `BACK_APPLY`, which clears exactly
that depth before the board is read again. So the reduction now drives only the
state register. Cycles and grids are **byte-identical to v5 on all 3,739 RTL
runs**, and Fmax rose to 72.30 MHz.

**v7 — the row tournament does not need a cycle.** The candidates it reads are
written by SCAN and untouched until the guess is placed, so the row winners are
registered during APPLY and `PICK_ROWS` disappears. A guess costs two cycles
instead of three. The tournament's combinational path is unchanged, so this
costs no frequency: 72.05 MHz, within fitter noise of v6. Grids are identical
everywhere; each puzzle loses exactly one cycle per guess. That is 4.83% of the
513-board set and 5.23% of the published-holdout mean.

Two variants were measured and rejected, with sources and reports kept in
`logs/experiments/`: registering per-cell candidate counts in SCAN reaches the
same cycle count but costs 323 registers and 1.2 MHz, and rewriting the
`first_digit` popcount tests as `v & (v-1)` is the same function but fits at
63.10 MHz and 19,164 LEs.

### A measurement caveat

v7 solves hard1 in 202 cycles rather than 217, but the reported application
count stays at **483**. The course application polls `HOST_REG(XLR_DONE_RI)` in
a busy loop, so a saving smaller than one poll interval never reaches the
reported number. The improvement is real — it is visible in the direct RTL
counts and in the published-holdout mean — but on the four course boards the
score improves through frequency alone. Do not read an unchanged application
count as an unchanged solver.

### Downloads

- **k5_xbox_sudx_scan.sof**: Quartus programming file, built for the 50 MHz course default.
- **k5_xbox_sudx_scan.svf**: alternate programming format.
- **DESIGN_WALKTHROUGH.md**: full explanation; section 21 covers v6 and v7.

The RTL was built from **5d93fab** and matches tag **v7**. The fitter and timing
analyzer both report zero errors and zero non-justified warnings. The whole
build took about ten minutes with a 5m40s fit, against roughly 27 minutes of
fitting with congestion retries at v5 — removing the wide fanout made the design
easier to route as well as faster.

At 50 MHz the system has 2.162 ns of setup slack, so `comp_fpga sudx_scan -mhz 55`
is a reasonable next experiment. **No clock above 50 MHz has been built or
verified here**, and the shipped bitstream is the 50 MHz one.

```sh
set_k5_terminal

launch_k5_app sudx_scan -asl sud_shared -gpv hard1
```
